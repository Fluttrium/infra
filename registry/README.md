# Приватный реестр пакетов (РФ) + разделение на два репозитория

Цель: хранить пакеты у себя в РФ, не зависеть от npmjs.com, и держать **форк Vendure**
отдельным репозиторием от **инстанса**.

## Архитектура

```
РФ-ВПС:
  • Verdaccio (этот compose)        ← приватный npm-реестр + кэш публичного npm
  • Git (self-hosted: Gitea/GitLab) ← репозитории

Репо A:  fluttrium-core      (форк/обёртка Vendure)  → publish в реестр как @fluttrium/*
Репо B:  fluttrium-instance  (этот проект: commerce, storefront, codegen, provisioning,
                              plugins) → ставит зависимости ИЗ твоего реестра, не из npmjs
```

## 1. Поднять реестр на ВПС

```bash
cd infra/registry
docker compose up -d            # http://ВПС:4873
```

В прод — закрой HTTPS (nginx/caddy) на `npm.твой-домен.ру`, порт 4873 наружу не публикуй.

Создай пользователя (один раз), затем в `config.yaml` поставь `max_users: 0`:

```bash
npm adduser --registry https://npm.твой-домен.ру
```

## 2. Направить инстанс на твой реестр (Bun читает .npmrc)

В корне репо-инстанса создай `.npmrc` (скопируй из `.npmrc.example`):

```ini
# всё тянем через твой реестр (он проксирует и кэширует публичный npm)
registry=https://npm.твой-домен.ру/
# токен авторизации (из ~/.npmrc после npm login), храни в секрете
//npm.твой-домен.ру/:_authToken=${NPM_TOKEN}
```

Аналог в `bunfig.toml`:

```toml
[install]
registry = "https://npm.твой-домен.ру/"
# или только для своего скоупа:
# [install.scopes]
# "@fluttrium" = { url = "https://npm.твой-домен.ру/", token = "$NPM_TOKEN" }
```

После этого `bun install` ходит только в твой реестр. npmjs.com больше не нужен —
Verdaccio один раз скачал пакет и хранит у себя.

## 3. Vendure: форк vs зеркало

**Зеркало (рекомендую для старта, 90% пользы):** в `config.yaml` у `@vendure/*` стоит
`proxy: npmjs`. Verdaccio кэширует официальные пакеты у тебя на ВПС. Ты независим от
npmjs.com, версии зафиксированы, но **код не поддерживаешь сам**. Если надо пропатчить —
публикуешь свою версию поверх (см. ниже).

**Форк (полное владение кодом):** отдельный репо `fluttrium-core`:

```bash
git clone https://github.com/vendure-ecommerce/vendure.git fluttrium-core
cd fluttrium-core && git checkout v3.6.4        # зафиксируй версию
# ... твои правки в packages/* ...
# собрать и опубликовать пакеты в свой реестр:
npm publish --registry https://npm.твой-домен.ру   # для каждого нужного @vendure/* пакета
```

Затем в `config.yaml` у `@vendure/*` **убери** `proxy: npmjs` (сделай приватным) — инстанс
будет брать твои сборки. Учти: поддержка форка (секьюрити-патчи, апгрейды) — на тебе.

> GPL: и зеркало, и форк — это норм, пока ты хостишь сам (SaaS) и не раздаёшь коробку.

## 4. Разделение репозиториев

- **Репо B (инстанс)** = текущий проект. Из него можно убрать ничего — он уже потребляет
  Vendure как зависимость. Меняется только источник: `.npmrc` → твой реестр.
- **Репо A (core)** = форк Vendure (если идёшь по пути форка). Публикует пакеты в реестр.
- Связь между ними — **только через реестр** (версии), не через общий код. Это и даёт
  «работать по каждому отдельно».

CI: репо A собирает и публикует `@fluttrium/...@x.y.z` → репо B обновляет версию в
`package.json` и пересобирает свой Docker-образ. Чисто, разделяемо, воспроизводимо.

## Альтернативы Verdaccio (если захочешь всё-в-одном)

- **Gitea** (self-hosted, лёгкий, РФ-дружелюбный) — даёт и git, и встроенный npm-реестр.
- **GitLab CE** (self-hosted) — git + CI + npm package registry в одном.
- **Nexus Repository OSS** — тяжелее, но умеет npm/docker/maven вместе.

Verdaccio проще всего, если нужен именно реестр; Gitea — если хочешь git+реестр одним сервисом.
